# 农产品融销一体平台 - 项目设计文档

> 版本：v1.2
> 更新时间：2026-07-10

---

## 一、用户角色

| 角色 | 代码 | 权限 |
|:---|:---|:---|
| 农户 | `farmer` | 发布农产品、融资申请、专家咨询、个人中心 |
| 买家 | `buyer` | 浏览商品、下单购买、购物车、专家咨询、个人中心 |
| 专家 | `expert` | 发布知识、回答问题、查看预约 |
| 银行 | `bank` | 审批融资、智能匹配 |
| 管理员 | `admin` | 全部管理功能 |

## 四、状态值规范

| 类型 | 值 | 说明 |
|:---|:---:|:---|
| 通用开关 | 0/1 | 0关/禁用 1开/正常 |
| 订单状态 | 1-5 | 1待付款 2待发货 3待收货 4已完成 5已取消 |
| 融资状态 | 0-2 | 0申请中 1已通过 2已驳回 |
| 问答状态 | 0/1 | 0未回答 1已回答 |
| 预约状态 | 0-2 | 0待处理 1已完成 2已拒绝 |

## 五、命名规范

- 表名：`tb_模块_功能`
- 字段名：小写+下划线，如 `user_name`
- 接口路径：`/模块/资源/操作`
- Java类名：大驼峰 `UserService`
- Java方法名：小驼峰 `getUserById`

## 七、实现备注（与上述设计的差异，持续更新，最近 2026-07-14）

> 以下为实际代码与本文档前文不一致或扩展之处。**实现以代码为准，前端已与后端对齐。**

### 7.1 接口路径差异

| 模块 | 文档原路径 | 实际实现路径 | 原因 |
|:---|:---|:---|:---|
| 我的预约 | `GET /reserve/list` | `GET /reserve/my` | 语义更清晰（"我的"） |
| 专家的预约 | `GET /reserve/expert/list` | `GET /expert/reserve/list` | 归到专家控制器下，按当前专家 token 解析 |
| 处理预约 | `PUT /reserve/{id}/status` | `PUT /expert/reserve/{reserveId}/status` | 同上，且校验处理人为该专家 |
| 当前专家信息 | `GET/PUT /expert/info` | `GET/PUT /expert/my/info` | 避免与公开的 `/expert/{userName}` 在 JWT 白名单 `/expert/*`（单段）上冲突，将受保护接口移到二级路径 |
| 删除知识评论 | `DELETE /discuss/{discussId}` | `DELETE /knowledge/discuss/{discussId}` | 统一在 knowledge 控制器下 |

### 7.2 已补齐的文档要求（原实现缺失）

- `DELETE /question/{id}`（文档 8 节要求，原缺失，已补）。
- MyBatis-Plus 分页拦截器 `MybatisPlusConfig`（否则所有 `selectPage` 失效）。
- 全局异常处理 `GlobalExceptionHandler`（统一 `Result` 返回）。
- `Expert` 实体主键注解 `@TableId(type=INPUT)`（否则按主键查询/更新失效）。

### 7.3 权限口径说明

- **问答详情 `GET /question/{id}`**：本文档第 8 节标注权限为"提问人、expert"（需登录）；而《专家助力模块设计文档》3.1 节将其列为"公共访问"。**实现采用本文档口径——需登录后访问**。

### 7.4 关键数据约定

- `tb_question.expert_name` 与 `tb_reserve.expert_name` 存储**专家的 `user_name`（账号名）**，而非 `real_name`。前端在提问/预约时传专家 userName；专家端按自身 userName 过滤。
- 知识列表：公共查询（未指定 ownName）仅返回已发布(status=1)；按自身 ownName 查询时返回含草稿的全部。新建知识默认 status=1（发布）。

### 7.5 后台管理模块（超出本文档第 11 节的扩展）

原第 11 节仅含用户列表/修改/删除。实际实现扩展如下：

**用户管理（管理员）**
- `GET /admin/users`（增加 `role`、`keyword` 过滤）
- `POST /admin/user`（新增任意角色用户；role=expert 时自动建 `tb_expert` 资料）
- `PUT /admin/user/{userName}`（修改资料/角色/状态；角色变更时同步专家资料）
- `PUT /admin/user/{userName}/status`（启用/禁用）
- `DELETE /admin/user/{userName}`（保护：不可删除自己、不可删除最后一个管理员）
- 所有 `/admin/**` 接口在控制器内校验 `role==admin`（JWT 拦截器仅验签不查角色）

**专家管理（管理员）**
- `GET /admin/experts`、`POST /admin/expert`、`PUT /admin/expert/{userName}`、`DELETE /admin/expert/{userName}`

**角色申请（新增模块）**
- 新增表 `tb_role_application`（见 `database/role_application.sql`）。
- `POST /user/apply-role`（农户/买家提交，申请成为 专家/银行；禁止申请 admin，防越权）
- `GET /user/my/applications`（我的申请记录）
- `GET /admin/applications`、`PUT /admin/application/{id}`（管理员审核：通过→变更 `tb_user.role`，目标为专家则自动建 `tb_expert` 资料；驳回→记审核备注）

### 7.6 角色获取方式总览

| 角色 | 获取方式 |
|:---|:---|
| 农户 / 买家 | 自助注册 `POST /user/register` |
| 专家 / 银行 | 管理员添加（`POST /admin/user` 或 `/admin/expert`）**或** 申请审核（`POST /user/apply-role` → `PUT /admin/application/{id}`） |
| 管理员 | 仅由管理员添加（申请接口不允许 target=admin） |

### 7.7 前端注册表单角色限制（与 7.6 节对齐）

- 注册页 `Register.vue` 仅提供「农户」「买家」两个角色选项（原先表单含「专家」）。与 7.6 节一致：**专家/银行须经管理员添加或角色申请审核开通，不支持自助注册为专家**。表单内增加提示，引导用户「先以农户/买家注册登录，再在『个人中心 → 角色申请』提交申请」。
- 后端 `POST /user/register` 接口本身仍开放（第 1 节"所有"，指无需登录即可调用），前端仅是不再提交 expert 角色，并非接口限制。

### 7.8 后台商品/融资管理接口补齐与口径（第 11 节）

- 第 11 节要求的 `GET /admin/products`、`PUT /admin/product/{orderId}`、`DELETE /admin/product/{orderId}`、`GET /admin/finances` 原后端缺失（前端 `AdminProduct.vue`/`AdminFinance.vue` 报"加载失败"），现已于 `AdminController` 补齐，均经 `requireAdmin` 校验。
- **融资审核路径**：第 11 节指定 `PUT /admin/finance/{financeId}`，**未单独实现**；管理员审核复用既有 `PUT /finance/apply/{financeId}`（`FinanceController`，银行与管理员共用同一审批接口，请求体 `FinanceApprovalRequest{status,remark}`）。前端 `approveFinance(id, data)` 即调用该路径。
- `AdminProduct.vue`/`AdminFinance.vue` 已按真实实体字段重写：商品用 `Product`（`title/content/price/picture/type/orderStatus/ownName`，无库存字段）；融资用 `Finance`（`realName/money/rate/repayment/status(0申请中/1已通过/2驳回)/createTime`）。

### 7.9 前端入口与个人中心（公共功能，2026-07-14）

- 顶部「个人中心」入口（`AppHeader.vue`）：farmer/buyer/expert 进入各自个人中心；**admin/bank 无个人中心页，点击回首页**（避免跳到不存在的 `/admin/profile`、`/bank/profile` 导致 404）。
- `farmer/Profile.vue`、`buyer/Profile.vue` 复用通用 `views/Profile.vue`，其中含「角色升级申请」入口（农户/买家可见，跳 `/role-application`），与 §7.5 角色申请模块衔接。
- 默认头像路径统一为 `/images/default-avatar.png`（原先漏 `/images/` 前缀导致裂图）。
- 多个独立页（专家详情、知识/问答列表、预约专家、角色申请、通用个人中心）统一增加「← 返回」按钮；各角色布局页（farmer/buyer/expert/admin/bank）已有侧边栏导航，不加。

### 7.10 商品图片字段统一为 picPath（2026-07-14）

- `Product` 实体图片字段由 `picture` 改为 `picPath`，用 `@TableField("picture")` 显式映射到 DB 列 `picture`（**DB 列不变、无需迁移**）。这样 API/JSON 字段与知识 `picPath`、轮播图 `picPath` 在前端统一为 `picPath`，公共商品页可直接显示商品图。
- `ProductRequest`、`ProductServiceImpl`、`AdminController.adminUpdateProduct`、前端 `AdminProduct.vue` 同步改为 `picPath`；种子数据 `seed_data_20260714.sql` 仍写 DB 列 `picture`（正确）。
